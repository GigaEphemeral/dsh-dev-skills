# Budget Auditor — Token 预算审计

token 是真实成本：**先定量、再执行、后结算、以实测为准。**（当前纪律+文件先行；工具化属插件阶段。）

## 触发场景
- 里程碑开工分配预算（研究/开发分账）
- 阶段结束结算实际消耗对比预算
- 需注入上下文/恢复记忆控预算
- 需统计缓存命中率入看板；上下文压力适配 /compact

## 工作流程
1. **预算分配**：里程碑五字段（含 token 预算），预算表 JSON+MD，PM 拍板。
2. **执行期纪律**：延迟加载（只读入口+当前目标+直接引用）；恢复记忆 ≤1000；知识注入 ≤800；长文沉文件。
3. **阶段结算（必跑）**：`node tools/token-ledger.mjs <workspace> --out ledger-<日期>.json` → `input+output` 为实际新增 → 对比预算（超额不阻断但记录，秒级时间戳）→ 缓存命中率入看板。
4. **/compact 适配**：/compact 是会话内压缩（上下文→摘要）；本体系记忆是**外部可检索知识层**，二者互补。恢复策略：按「当前 workspace+相关度」从知识库召回（RRF），预算 ≤800 注入，不整库读；compact 摘要经 R9 提炼入知识库。
5. **节流降耗**：上下文压力/超预算信号时 → 延迟加载→降注入→触发 /compact→结束冗余子任务。

## 边界纪律
- 预算是参考值，实际以实测为准；超额不阻断但必记录。
- 结算记账是阶段门禁必做项；预算分配是 PM 职责。
- 工具化（tokenMeter/compaction/看板）在插件阶段落地；当前纪律+文件先行。
