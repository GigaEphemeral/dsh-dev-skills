# 任务拆解、进度总结与 todo 控制（references · R6-ts-developer）

> 开发/架构/测试**共用一套**。PM 决定（2026-09-20）。

## 项目 Task 拆解与规划

1. **拆解输入**：Spec（含架构师可行性结论）+ 架构方案 + 测试方案。
2. **拆解规则**：按「可独立验证」拆——每任务有 明确产出 + 验收口径（golden case/边界输入）；标依赖（depends_on）；标风险（🔧 项需架构师复核）；顺序先核心闭环后外围。
3. **任务卡片**：
   ```
   T<id>: <一句目标>
   - 范围: In/Out
   - 产出: <文件/接口/测试>
   - 验收: <可测口径>
   - 依赖: [前置任务]
   - 负责角色: 开发/架构/测试
   - 风险: 无/🔧(技术难度需架构师)
   ```
4. **规划输出**：任务清单（有序）+ 依赖关系图 + 里程碑分批 + 预算分配（如启用）；交 PM 确认后再派发（写操作授权门）。

## 进度总结（方案 C：todo 工具绑定，强制）

- **todo 工具绑定**：开工前列完整任务清单（每项一句、可判断完成、含顺序）；执行中每完成一项立即勾选（不批量积压），卡住项标「阻塞:原因」；大任务拆子任务（每子任务 ≤ 一个可验证产出）。
- **每 turn 结束输出进度小结**：
  ```
  进度小结 · <YYYY-MM-DD HH:mm:ss>
  - 完成: <项，各带证据>
  - 进行中: <未完成 + 卡点>
  - 下一步: <1-2 条最优先动作>
  ```
- **时间戳精确到秒**（`YYYY-MM-DD HH:mm:ss`）；进度变化记录到开发流程记录文档（秒级时间戳）。

## todo 文件拆分规则

- **按大阶段任务拆分 todo 文件**：一个大项目可多个 todo 文件（每大阶段一个）；大阶段少的就用一个文件。
- 目的：避免单文件过长、便于按阶段回顾。
- 示例：`TODO-stage1-skills.md` / `TODO-stage2-personas.md` / `TODO-stage3-plugin.md`。
