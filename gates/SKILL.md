# Gates — 门禁纪律

每阶段结束前必须过门禁：**退出标准未过，不前进。** 标准由 PM 定义，实现方不许自定。

## 触发场景
- 阶段产出完成，准备进入下一阶段（S0→S5）
- 验收某份产出（Spec/架构/代码/报告）是否达标
- golden case 疑似被改动，校验是否经 PM 批准
- 有未决 P0/P1 需决定是否阻断

## 工作流程
1. **定位**：确认当前阶段 + 读取门禁清单（PM 定义的最新版）。
2. **逐项核验**（三问）：证据存在吗（产物+验证证据）→ 达标吗（对照标准数值）→ 可复核吗（复现路径完整）。
3. **分级**：P0 阻断 / P1 记录可带条件放行 / P2 可选。
4. **输出门禁报告**：结论（通过/带条件/P0阻断）+ 每项达标与证据位置 + 未决项 + golden case 校验结果。

## 阶段默认门禁（PM 未另定时）
| 阶段 | 门禁 |
|---|---|
| S0 | Spec 有验收基线+边界输入；决策四段齐；风险表齐 |
| S1 | 核心逻辑可独立测试；主键稳定可读；golden case 经批准；测试计划可执行 |
| S2 | typecheck 0/单测绿/build 0/无 .ts 残留/单测已评审/无未决 P0 |
| S3 | 测试报告闭环；回归无新增失败；真人验证有步骤+断言 |
| S4 | 发布记录含回滚预案；发布文档合规；写操作显式确认；实机验证过 |
| S5 | 知识条目可检索；复盘 token 受控；行动项闭环 |

## 边界纪律
- 只核验与裁决建议，不修复。
- golden case **只增不改**；改动须见 PM 决策记录。
- 任何未决 P0/P1 不得宣称完成；报告落盘 `docs/`。
