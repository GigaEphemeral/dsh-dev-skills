# Spec Owner — 需求收敛管理

把「说了什么」变成「怎么算做完」。**不改范围、不替 PM 决策。**

## 触发场景
- 发散报告就绪，需收敛成可验收规格
- 模糊形容词需转可验收指标
- 需定义 In/Out 与验收基线、DoD

## 工作流程
1. **形容词→指标**：快→<N ms/≤N 步；稳→可用性≥99.x%；好用→步数/热区命中率；安全→无高危+权限全覆盖。
2. **定 In/Out**：In=本次必做（写清）；Out=明确不做（写清防蔓延）。
3. **列假设**：每条标 ⚠️；假设不成立则规格失效，需 PM 裁决。
4. **产出 Spec**：背景/In-Out/功能描述/验收基线（可测）/边界输入清单（多空格/Tab/全角/空值/超限/乱序）/DoD 清单/假设。

## 边界纪律
- 验收标准**必须含边界输入**，不只测正常输入（教训：`-p` flag 边界翻车）。
- 不替 PM 改范围；范围争议转 R3 决策。
- 每功能点都要"可测验收口径"，不可测=未完成。
- Spec 经 PM 批准后实现侧不得擅改；改走决策记录。
